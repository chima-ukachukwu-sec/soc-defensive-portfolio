# Security Policy

## Reporting a problem

Email **chima.ukachukwu.sec@gmail.com** with `SECURITY` in the subject line.

This repository holds written methodology rather than running code, so the
concerns here are different from a software project.

## What I want to hear about

- **Anything that should not be public.** If you believe something here
  identifies a client, an environment, or a live finding, tell me and I will
  remove it first and discuss afterwards.
- **Anything operationally usable by an attacker.** Content is sanitized so
  that it teaches method without providing a working attack. If something
  crossed that line, that is a mistake worth reporting.
- **Anything factually wrong** in a way that would mislead a practitioner who
  relied on it.

I will acknowledge within 72 hours.

## What has been removed deliberately

Working exploits, client-identifying details, indicators of compromise, and
detection logic belonging to an employer are not published here. Their absence
is intentional and is not an oversight to be corrected by contribution.
